目标检测模型技术综述

目标检测模型技术综述：架构演进、训练方法与部署实践

本文档系统梳理目标检测领域两条主线——基于 CNN 的 YOLO 系列与基于 Transformer 的 DETR 系列——的发展演进历史、架构组件拆解、训练方法、评估指标及量化部署实践，为迈智眸算子场景选型提供技术参考。

一、什么是目标检测

目标检测（Object Detection）是计算机视觉中最基础也最成熟的任务之一，其核心目标是在图像中同时完成”是什么”（分类）和”在哪里”（定位）两个子任务——既要识别出图像中所有感兴趣目标的类别，又要精确定位每个目标的边界框（Bounding Box）。

1.1 与图像分类的本质区别

维度 图像分类 目标检测
输出 单个类别标签 N 个 (类别, 边界框) 对
空间信息 丢弃 保留并回归
目标数量 固定为 1 不定，需自行确定
核心挑战 特征表达 特征表达 + 定位 + 密集场景去重

1.2 核心挑战

  • 尺度变化：同一类目标在不同图像中尺寸差异巨大（从 8×8 像素到覆盖全图）
  • 密集场景：目标间严重遮挡与重叠，检测器需区分相邻目标
  • 小目标：深层特征图分辨率低，小目标信息在下采样中丢失
  • 实时性：工业场景要求低延迟推理（< 30ms）

1.3 两大技术路线

目标检测的发展沿着两条主线演进：

CNN 路线：R-CNN → Fast/Faster R-CNN → YOLO v1~v12 → D-FINE
                                                         ↓
Transformer 路线：DETR → Deformable DETR → RT-DETR → LW-DETR → RF-DETR
                                                                      ↓
                                                              FSDETR (频域增强)
  • CNN 路线：基于锚框/无锚框的密集预测，依赖 NMS 后处理，工程成熟、部署友好
  • Transformer 路线：基于集合预测的端到端检测，无需 NMS，全局建模能力强，近期在精度和速度上已追平甚至超越 CNN 路线

二、YOLO 系列：CNN 检测器的演进主线

2.1 两阶段检测器（背景知识）

在深入 YOLO 之前，需了解两阶段检测器的基本范式，因为 YOLO 的很多设计是对其的简化与改进。

R-CNN (2014) 开创了”先提候选区域再分类”的两阶段范式：

输入图像 → Selective Search 生成 ~2000 个候选区域 → 每个 ROI 独立过 CNN → SVM 分类 + 回归

问题：速度极慢（一张图 47s），因为对 2000 个候选区域逐一做 CNN 前向。

演进链路：

模型 年份 核心改进 速度
R-CNN 2014 Selective Search + CNN + SVM ~47s/张
Fast R-CNN 2015 RoI Pooling 共享卷积特征 ~0.3s/张
Faster R-CNN 2015 RPN 替代 Selective Search，端到端训练 ~0.05s/张
Mask R-CNN 2017 RoI Align + 分割分支 ~0.05s/张

两阶段的核心流程：

输入图像 → CNN 骨干 → FPN 多尺度特征 → RPN 生成候选框 → RoI Pooling → 分类头 + 回归头 → NMS → 输出
         └ 第一阶段：生成候选 ┘                └ 第二阶段：精确分类和回归 ┘

2.2 YOLO 系列演进

YOLO（You Only Look Once）将检测统一为单阶段回归问题，成为实时检测的标杆。

2.2.1 架构通用范式

尽管 YOLO 版本迭代频繁，其核心架构始终遵循”骨干-颈部-头部”三段式：

输入图像 → Backbone (特征提取) → Neck (多尺度融合) → Head (分类+回归) → 后处理
组件 职责 典型实现
Backbone 提取多层级视觉特征 DarkNet (v3), CSPDarkNet (v4/v5), C2f/C3k2 (v8~v12)
Neck 融合不同分辨率特征，覆盖多尺度目标 FPN, PANet, BiFPN, ELAN-W
Head 并行预测类别概率和边界框坐标 解耦头 (Decoupled Head), Anchor-based / Anchor-free

2.2.2 关键版本里程碑

版本 年份 核心创新 意义
YOLOv1 2016 单阶段回归，7×7 网格，无锚框 首个实时检测器（45 FPS）
YOLOv2 2017 引入锚框、Batch Norm、多尺度训练 精度大幅提升
YOLOv3 2018 DarkNet-53 + FPN 三尺度预测 小目标检测能力提升
YOLOv4 2020 CSPDarkNet + PANet + Mosaic 增强 系统化训练策略整合
YOLOv5 2020 工程优化，PyTorch 原生 最广泛部署的版本
YOLOv6 2022 RepVGG 重参数化 + Decoupled Head 硬件友好的推理结构
YOLOv7 2022 E-ELAN + 辅助训练头 训练效率提升
YOLOv8 2023 Anchor-free + C2f 模块 + TaskAlignedAssigner 全面转向无锚框
YOLOv9 2024 PGI + GELAN 可编程梯度信息，防止信息瓶颈
YOLOv10 2024 NMS-free 双标签分配 真正端到端 YOLO
YOLOv11 2024 C3k2 模块 + C2PSA 空间注意力 更轻量的特征提取
YOLOv12 2025 区域注意力机制 (A2) CNN 中引入 Transformer 级注意力

2.2.3 Anchor-based vs Anchor-free

这是 YOLO 系列最重要的架构分水岭：

Anchor-based（YOLOv2~v7）：

特征图每个位置预设 K 个锚框（不同尺度+长宽比）
  → 回归偏移量：Δx, Δy, Δw, Δh（相对于锚框）
  → 分类：C 个类别概率 × K 个锚框
  → NMS 去除冗余框

锚框通过 K-means 聚类数据集 GT 框得到，需要针对不同数据集重新设计。

Anchor-free（YOLOv8+）：

特征图每个位置直接预测：
  → 中心点偏移 + 框宽高（或到四边的距离）
  → 分类：C 个类别概率
  → 无需锚框设计，无需 NMS（v10+）

优势：消除了锚框超参设计，简化训练流程，迁移到新数据集时更灵活。

2.2.4 核心模块演进

CSP 结构（Cross Stage Partial）：YOLOv4 引入，将输入特征分为两部分，一部分走密集卷积，另一部分直接 concat，减少梯度重复计算：

输入 → Split → [Dense Block] ──┐
         └───── Conv ──────────┤
                               → Concat → 输出

C2f 模块（YOLOv8）：CSPNet 的改进版，用更少的参数获得更丰富的梯度流：

输入 → Conv → Split → [Bottleneck × N] ──→ Concat → Conv → 输出
                       └── 残差连接 ──────────┘

重参数化（RepConv, YOLOv6）：训练时用多分支结构（3×3+1×1+Identity），推理时融合为单个 3×3 卷积，兼顾训练效果和推理速度。

2.3 D-FINE：CNN 路线的最新进展

D-FINE (2024) 将 DETR 的最优实践融入 YOLO 框架，引入了细粒度分布优化（FDR）和目标感知分类（GO-LDS），在 COCO 上达到 54.0 AP（small），成为 CNN 路线精度最高的实时检测器之一。

三、DETR 系列：端到端检测的 Transformer 革命

3.1 原始 DETR (2020)：集合预测范式

DETR（DEtection TRansformer）是 Facebook Research 在 2020 年提出的目标检测架构，首次将 Transformer 引入目标检测，彻底抛弃传统检测器中手工设计的组件（锚框、NMS 等），实现了真正的端到端检测。

3.1.1 架构组成

输入图像 → CNN 骨干(ResNet) → 1×1 Conv 降维 → Transformer 编码器 → Transformer 解码器 → 预测头 → 输出
                                                            ↑
                                                    Object Queries (N=100)
组件 职责
CNN 骨干 用 ResNet-50 提取特征图，1×1 卷积降维为序列
Transformer 编码器 自注意力建模全局关系，加位置编码
Transformer 解码器 Object Queries 通过交叉注意力”查询”目标
预测头 分类头（C+1 类，含 ∅ 无物体类）+ 回归头

3.1.2 核心思想：集合预测

DETR 将检测建模为集合预测问题：

  • 模型输出固定 N=100 个预测（覆盖大多数图像的目标数）
  • 用匈牙利算法做二分匹配，将每个 GT 与唯一一个预测配对
  • 未匹配的预测被训练输出 ∅（无物体）
  • 推理时直接扔掉 ∅ 预测，无需 NMS

匹配代价 = 分类损失 + L1 框损失 + GIoU 损失

3.1.3 优势与不足

优势 不足
真正端到端，无需 NMS 训练收敛慢（500 epoch vs Faster R-CNN 的 12 epoch）
全局感受野，对遮挡/重叠更好 小目标性能差（仅单尺度特征）
架构简洁 推理速度不够快

3.2 DETR 家族演进

变体 年份 核心改进 解决的问题
DETR 2020 Transformer + 集合预测 + 匈牙利匹配 端到端检测范式
Deformable DETR 2020 可变形注意力 + 多尺度特征 训练加速 10 倍，小目标提升
DAB-DETR 2022 Anchor Box 作为 Query 加速收敛
DN-DETR 2022 去噪训练 进一步加速收敛
DINO 2022 对比去噪 + 混合 Query 选择 SOTA 精度
RT-DETR 2024 高效混合编码器 + 不确定性最小化 Query 选择 首个实时 DETR
LW-DETR 2024 更轻量设计 RF-DETR 前身
D-FINE 2024 细粒度分布优化 CNN 框架融入 DETR 最优实践
RF-DETR 2026 NAS 搜索 + DINOv2 骨干 首个突破 60 AP 的实时检测器
FSDETR 2026 频域-空间协同建模 小目标检测增强

3.3 RT-DETR：首个实时 DETR

RT-DETR (2024) 是百度提出的实时检测 Transformer，在速度上首次匹敌 YOLO，同时保持更高的精度。

核心创新——高效混合编码器：

骨干多尺度特征 {P3, P4, P5}
    ↓
AIFI（帧内特征交互）：仅对高层特征 P5 做全局自注意力
    ↓
CCFM（跨尺度特征融合）：将 P5 与 P3/P4 融合
    ↓
Decoder

关键设计：只对最高层特征做昂贵的全局注意力（因为高层特征图小，计算量可控），低层特征通过简单的卷积融合，避免了对所有尺度做注意力的计算爆炸。

3.4 RF-DETR：NAS 驱动的 SOTA

RF-DETR (ICLR 2026) 由 Roboflow 与 CMU 联合提出，通过端到端权重共享 NAS 一次训练即可生成从 nano 到 2x-large 的全部尺寸配置。

五大可调旋钮：

旋钮 作用 搜索空间
Patch Size 精度-延迟权衡 {8,10,12,16,20,24,32}
解码器层数 延迟控制（可降至 0 层） {0,1,2,3,4,5,6}
Query 数量 适配目标密度 动态排序丢弃
图像分辨率 小目标 vs 速度 320~960
窗口数 注意力范围 {1,2,4}

关键成果： - RF-DETR (nano)：48.0 AP，2.3ms，比 D-FINE (nano) 高 5.3 AP - RF-DETR (2x-large)：60.1 AP，首个突破 60 AP 的实时检测器 - 采用 DINOv2 自监督预训练骨干，跨域泛化能力强

3.5 FSDETR：频域-空间协同增强小目标

FSDETR 以 RT-DETR 为基线，提出三个即插即用的改进模块：

模块 位置 核心创新
SHAB 骨干深层 只对一半通道做自注意力，省 75% 计算
DA-AIFI 编码器 可变形注意力替代全局注意力，自适应聚焦目标区域
FSFPN + CFSB 特征金字塔 频域 FFT 滤波 + 空间 Scharr 边缘提取并行融合

核心洞察：小目标的高频信号在频域是全局可见的，频域卷积以 O(C log N) 代价获得准全局感受野。在 VisDrone2019 上，FSDETR 以 14.7M 参数（比基线少 26.5%）取得 40.5 AP50 和 13.9 AP_S。

四、基于 DINO 骨干系列：自监督预训练赋能检测

4.1 为什么需要自监督预训练

预训练+下游任务微调范式的本质是知识的复用与迁移。然而在许多垂直领域（工业检测、医疗影像、遥感），标注数据稀缺且成本高昂，推动了自监督预训练的发展。

当前 CV 领域两大自监督范式：

范式 核心思想 代表方法
对比学习 构建正负样本对，优化相似度度量 SimCLR, MoCo, DINO
掩码图像建模 (MIM) 遮蔽图像区域，重建被遮蔽部分 MAE, BEiT, DINOv2

4.2 DINO：自监督蒸馏

DINO（Self-Supervised DINO, 2021）的核心是自蒸馏：教师网络（EMA 学生网络）产生软标签，学生网络学习对齐。关键创新是用多裁剪策略增强正样本多样性。

4.3 DINOv2：互联网规模预训练

DINOv2 (2023) 将自监督预训练推向互联网规模：

  • 训练数据：1.42 亿张图像（LVD-142M），自动收集+去重
  • 架构：ViT (ViT-S/B/L/g)
  • 方法：结合 DINO（对比学习）+ iBOT（掩码图像建模）双重目标
  • 效果：无需任何标签，学到通用视觉特征，在 ImageNet 线性探测 86.5% Top-1

4.4 DINOv2 在检测中的应用

RF-DETR 用 DINOv2 替代传统 CNN 骨干，带来两大优势：

  1. 跨域泛化：DINOv2 的互联网规模预训练知识比 COCO 微调更通用，在 RF100-VL（100 个不同领域数据集）上泛化能力显著优于 CNN 骨干
  2. 无需标签：自监督预训练不依赖标注数据，可利用海量无标注图像

实验证明：DINOv2 骨干比 CAEv2（+1.3 AP）、SAM2 Hiera-S、SigLIPv2 均更优。

五、训练方法

5.1 数据增强

策略 描述 适用场景
Mosaic 4 图拼接，丰富背景和小目标 YOLOv4~v7
MixUp 两图加权混合 YOLOv5~v7
水平翻转 + 随机裁剪 最基础增强 RF-DETR（避免数据偏差）
Copy-Paste 从其他图复制目标粘贴 实例分割
多尺度训练 训练中随机改变输入分辨率 YOLO 全系列

RF-DETR 的反直觉发现：激进的增强（如 VerticalFlip、Mosaic）隐含对 COCO 特性的先验假设，在真实场景中可能有害。仅用翻转+裁剪 + EMA 调度，反而获得更好的跨域泛化。

5.2 学习率调度

调度器 描述 特点
余弦退火 (Cosine) lr 按余弦曲线衰减到 0 YOLO 标准，但隐含 COCO 偏差
EMA 指数移动平均，维护权重滑动平均 RF-DETR 采用，更温和
Linear Warmup 前几个 epoch 线性升温 稳定训练初期

5.3 损失函数

目标检测损失由三部分组成：

总损失 = α · 分类损失 + β · 回归损失 + γ · 辅助损失

分类损失

损失 公式核心 特点
交叉熵 (CE) −∑yilog (pi) 基础，类别不平衡敏感
Focal Loss −α(1 − p)γlog (p) 降低易样本权重，聚焦难样本
Varifocal Loss (VFL) 对高 IoU 正样本加权 RT-DETR 原生，密集场景友好

回归损失

损失 公式核心 特点
L1 / Smooth L1 ∥xpred − xgt∥ 稳定梯度，但与 IoU 无关
IoU Loss 1 − IoU 尺度不变，但低重叠时梯度平坦
GIoU / DIoU / CIoU IoU + 惩罚项（中心距/宽高比） 解决低重叠梯度问题
Focaler-EIoU 重构低重叠区间梯度 FSDETR 采用，小目标友好

5.4 标签分配策略

标签分配决定”哪些 anchor/query 被视为正样本”：

策略 描述 代表模型
静态 IoU 阈值 IoU > 0.5 为正，< 0.3 为负 早期 YOLO
ATSS 自适应阈值（基于统计） 大多数现代检测器
TAL (TaskAlignedAssigner) 对齐度 = 分类得分^α × IoU^β YOLOv8+
匈牙利匹配 全局最优二分匹配 DETR 系列
双标签分配 (v10) 一对多匹配（训练）+ 一对一（推理） YOLOv10 NMS-free

5.5 知识蒸馏

知识蒸馏（Knowledge Distillation）是将大模型（教师）的知识迁移到小模型（学生）的技术，是检测模型轻量化的重要手段。Meta 提出的 EUPE 方案是该领域最新代表，其核心思想是先聚合、再蒸馏。

EUPE 三阶段蒸馏架构

Stage 1: 多个领域专家教师 → 1.9B 代理模型（知识聚合）
Stage 2: 代理模型 → 86M 高效学生（固定 256×256 分辨率）
Stage 3: 多分辨率微调（256/384/512 三尺度）

为什么不直接多教师→小模型？ 86M 小模型直接学习 3 个 1B+ 专家会”消化不良”——多教师特征空间差异大，小模型容量不足以同时吸收。先蒸馏到 1.9B 代理模型“消化”后，再迁移给小模型，效果显著提升。

蒸馏内容：中间特征而非 Logits

EUPE 蒸馏的不是分类 logits，而是中间特征（class token + patch tokens）：

蒸馏对象 损失函数 作用
Class token 余弦相似度 全局语义方向对齐
Patch tokens 余弦(0.9) + Smooth L1(0.1) 空间表示对齐，保留密集预测信息

关键设计：特征归一化——训练前用 500 个 batch 预计算各教师输出的 per-coordinate 均值和标准差，训练中固定使用 ((y - ) / ) 归一化教师输出，防止单教师主导梯度。

教师选择的反直觉发现

教师组合 效果
PEcore-G + DINOv3-H+ 图像理解 + 密集预测强，但 VLM 差
+ SigLIP2-G 反而损害 OCR（两个 CLIP 类模型特征冲突）
+ PElang-G（最终选择） OCR 与 VLM 大幅提升，不影响其他能力

启示：多教师不一定是 1+1≥2，需考虑特征空间兼容性。两个同类型教师（如两个 CLIP 类）可能“打架”。

对检测模型的借鉴意义

  • 特征级蒸馏优于 logit 级：保留更多空间信息，对密集预测任务尤其关键
  • 代理模型策略：当教师与学生容量差距过大时，引入中间“助教”模型可提升蒸馏效率
  • 数据质量 > 数据数量：EUPE 使用 1.69B 张 LVD 数据击败了 2.5B 张 MetaCLIP，再次验证数据质量的重要性

AP (mAP) PR 曲线下面积，IoU=0.5:0.95 平均 COCO 主指标
AP50 IoU=0.5 时的 AP 宽松标准，PASCAL VOC 传统
AP75 IoU=0.75 时的 AP 严格标准
AP_S 面积 < 32×32 的目标 AP 小目标检测能力
AP_M 32×32 ~ 96×96 的目标 AP 中等目标
AP_L 面积 > 96×96 的目标 AP 大目标

6.2 IoU (Intersection over Union)

$$IoU = \frac{|B_{pred} \cap B_{gt}|}{|B_{pred} \cup B_{gt}|}$$

IoU 衡量预测框与真实框的重叠程度，范围 [0, 1]。阈值越高，对定位精度要求越严格。

6.3 速度指标

指标 定义 注意事项
FPS 每秒处理帧数 受输入分辨率影响大
延迟 (ms) 单张推理耗时 需报告硬件+精度+batch
吞吐量 (img/s) 批量处理能力 受 batch size 影响

RF-DETR 的延迟标准化建议：GPU 连续推理会因功耗节流降频，应在两次前向间缓冲 200ms；精度和延迟必须用同一模型工件（FP16）测量，避免 FP32 报精度、FP16 报延迟的不一致问题。

七、量化部署

7.1 量化方法

方法 精度 压缩比 精度损失 适用场景
FP32 32 bit 1× 基准 训练
FP16 16 bit 2× < 0.5 AP GPU 推理标准
INT8 8 bit 4× 1~2 AP 边缘端/TensorRT
INT4 4 bit 8× 2~5 AP 极端资源受限

7.2 FP16 量化的陷阱

朴素 FP16 量化可能导致精度崩溃（如 D-FINE 从 55.0 AP 暴跌至 0.5 AP），根因：

  1. ONNX 导出中的张量索引偏移在 FP16 下精度不足
  2. 中间激活值域跨度过大，FP16 的 5 位指数无法覆盖
  3. softmax 的指数运算放大噪声

对策：导出时检查关键算子的数值范围，必要时保留 FP32 精度的敏感层（混合精度量化）。

7.5 边缘硬件选型指导

不同部署平台的算力特性差异巨大，检测模型的选型需与目标硬件匹配：

平台类型 典型硬件 算力范围 推荐模型 量化方案

EUPE 端侧延迟实测参考：ViT-T (6M) 在 iPhone 15 Pro CPU 上 256×256 分辨率仅 6.8ms，证明 6M 参数级别的模型完全可落地移端。但 ViT-B (86M) 在 512×512 分辨率下达 305ms，不适合实时场景。

部署选型决策树：

输入分辨率 ≤ 640？
├─ 是 → 延迟要求 < 10ms？
│   ├─ 是 → YOLOv8-n (INT8) + TensorRT/RKNN
│   └─ 否 → RF-DETR-nano (FP16) + TensorRT
└─ 否 → 算力 > 100 TOPS？

7.6 国产化部署注意事项

在国产化场景（昇腾/瑞芯微）中部署检测模型需注意：

问题 原因 对策
算子不支持 部分 DETR 特有算子（如可变形注意力）未实现 降级为标准注意力或回退到 CNN 路线
INT8 精度退化 量化校准数据不足 使用 PTQ + QAT 混合策略，关键层保留 FP16
动态形状 NPU 通常要求固定输入尺寸 预设常用分辨率，避免运行时动态 reshape
ONNX 转换 中间表示差异 使用官方转换工具（ATC/RKNN-Toolkit2），避免第三方 ONNX

8.2 迈智眸算子场景分类概览

迈智眸 8 大场景共 115 个算法任务，按 CV 类型分布：

CV 类型 占比 典型算法 推荐检测器
目标检测 ~70% 安全帽检测、人脸布控、车辆检测 YOLOv8/v11 或 RF-DETR

目标检测是迈智眸算子场景的核心算法类型（占比约 70%），技术选型直接影响平台整体能力。

8.3 检测器选型决策流程

Step 1: 确定延迟要求
├─ < 5ms（极致实时）→ YOLOv8-n (INT8)
├─ 5~15ms（实时）→ RF-DETR-nano (FP16) 或 YOLOv8-s (INT8)
├─ 15~40ms（准实时）→ RF-DETR-medium (FP16) 或 YOLOv8-m (INT8)
└─ > 40ms（离线分析）→ RF-DETR-2xlarge (FP16)

Step 2: 评估目标特性
├─ 小目标密集（航拍/监控）→ FSDETR 或 YOLOv8 + 高分辨率输入
├─ 跨域泛化（场景多变）→ RF-DETR + DINOv2 骨干
└─ 常规场景 → YOLOv8/v11 标准配置

Step 3: 确认部署平台
├─ NVIDIA GPU → TensorRT FP16，优先 RF-DETR
├─ Intel CPU → OpenVINO INT8，选择 YOLOv8
├─ 瑞芯微/昇腾 → RKNN/CANN INT8，选择 YOLOv8
└─ 移动 CPU → CoreML FP16，选择 EUPE-ViT-T 或 YOLOv8-n

8.4 与相关 CV 任务的关联

目标检测并非孤立任务，迈智眸平台同时涉及多种 CV 任务类型：

相关任务 与检测的关系 技术复用
语义分割 检测给出边界框，分割给出像素级标签 共享骨干网络（如 ResNet/ViT）；DeepLab 系列的多尺度融合思想被 YOLO Neck 借鉴
实例分割 检测 + 分割的结合 RF-DETR-Seg 直接从检测模型扩展分割头；YOLO-Seg 共享检测骨干
行为识别 检测 + 时序建模 先用检测器定位人体，再用 3D CNN / Transformer 分析动作时序
计数/密度估计 检测 + 跟踪 或 密度图回归 检测 + DeepSORT 是最成熟的计数方案

语义分割领域的 FCN 跳跃连接、DeepLab 空洞卷积与 ASPP 多尺度融合，与检测领域的 FPN/PANet 设计思想一脉相承，技术可互相借鉴。

九、总结

目标检测领域经历了从两阶段到单阶段、从 CNN 到 Transformer、从手工设计到 NAS 自动搜索的三重演进：

  1. CNN 路线（YOLO 系列）：工程成熟、部署友好、生态完善，是工业落地的首选。最新版本（v8~v12）已融合 Anchor-free、NMS-free、注意力机制等 DETR 优势。

  2. Transformer 路线（DETR 系列）：端到端、全局建模、跨域泛化强。RF-DETR 以 60.1 AP 标志着实时检测器进入新纪元，DINOv2 自监督骨干让”少标注、强泛化”成为可能。

  3. 融合趋势：两条路线正在融合——CNN 检测器引入 Transformer 注意力（YOLOv12），DETR 检测器采用 CNN 高效模块（RT-DETR 的 CCFM），频域增强（FSDETR）为两者提供通用增强策略。

  4. 部署实践：FP16 量化是 GPU 推理标准，但需警惕精度崩溃（D-FINE 从 55.0 AP 暴跌至 0.5 AP 的教训）；端侧部署需结合算子融合、结构化剪枝与知识蒸馏；国产化平台（昇腾/瑞芯微）的算子支持仍是瓶颈，DETR 特有算子可能需降级处理。

  5. 训练方法论：知识蒸馏是轻量化的关键手段——EUPE 的“先聚合再蒸馏”策略证明了特征级蒸馏优于 logit 级，多教师需考虑特征空间兼容性。数据质量 > 数据数量是颠扑不破的规律。

  6. 未来趋势：CNN 与 Transformer 两条路线正在融合（YOLOv12 引入注意力，RT-DETR 采用 CNN 模块）；自监督预训练（DINOv2）让“少标注、强泛化”成为可能；NAS 自动搜索（RF-DETR）正在取代手工架构设计。

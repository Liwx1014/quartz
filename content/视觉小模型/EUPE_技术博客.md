# EUPE：先聚合再蒸馏，86M 小模型凭什么通吃三大视觉任务？

> 还在为边缘设备上跑不动大视觉模型发愁？Meta 团队刚放出的 EUPE（Efficient Universal Perception Encoder），用一个 86M 的小模型，同时在图像理解、密集预测、VLM 三大类任务上**与同尺寸领域专家打平甚至反超**。来看看他们怎么做到的。

## 一、问题：鱼和熊掌为啥不能兼得？

智能眼镜、AR/VR、手机端……这些**边缘设备**算力有限、内存紧张，但用户需求却越来越复杂 —— 一会儿想识别物体（**图像理解**），一会儿想分割场景（**密集预测**），一会儿还想让它读图说话（**VLM 视觉-语言建模**）。

传统做法是：每个任务找一个最强的"专家"模型。

但尴尬的是 ——

- **CLIP 派**（SigLIP2、PEcore）：能读图说话，但分割能力拉胯
- **DINOv3 派**：分割/匹配能力一流，但"嘴笨"不会看图说话
- **SAM 派**：分割之神，但没法给你讲图片里有什么

想要一个"全能选手"？之前的方法比如 **RADIO** 和 **DUNE** 尝试用多教师蒸馏把多个专家能力合并，**但效果不理想** —— 小模型容量有限，直接"灌"给它多个异质教师的知识，反而消化不良。

Meta 这篇论文给出了一个非常反直觉但异常简单的解法

---

## 二、核心思路：**先聚合、再蒸馏**

是不是很反直觉？要做小模型，为什么要先训练一个 1.9B 的代理模型？

直觉是这样的：**让 86M 的小模型直接学 3 个 1B+ 的专家，它会被"撑爆"**。但如果我们先把这 3 个专家的知识**统一蒸馏**到一个 1.9B 的大代理模型（让它先"消化"），然后再让小模型从这个已经"消化完"的统一教师那里学，就能事半功倍。

直接看三阶段架构对比：

| **Stage 1** · 多教师 → 大型代理模型<br>*PEcore / PElang / DINOv3* | **Stage 2** · 代理模型 → 高效学生<br>*256×256 固定分辨率* | **Stage 3** · 多分辨率微调<br>*256 / 384 / 512* |
|:---:|:---:|:---:|

### 2.1 Stage 1：多教师 → 代理模型（统一知识）

**目标**：把多个领域专家的能力融合到一个 1.9B 参数的大型代理模型中。

**具体做法**：

1. **三教师并行推理**：输入同一张图片 \(x\)，同时送入三个冻结的教师编码器（参数不更新）：
   - **PEcore-G** (1.9B)：原生分辨率 448×448，擅长 VLM 和零样本分类
   - **PElang-G** (1.7B)：原生分辨率 448×448，提供 OCR 和语言能力
   - **DINOv3-H+** (840M)：原生分辨率 256×256，擅长密集预测
2. **同时送入学生模型**：代理模型是一个 1.9B 参数的 ViT-G，配备了 **4 个 register tokens**。
3. **计算蒸馏损失**：把代理模型的输出与每个教师的输出**分别**对比（详见 2.4 节），再把三个损失**简单相加**。

> **三个教师输出维度不同，怎么算损失？** 是的，每个教师都有自己的 Adapter 头来对齐学生输出。具体流程是这样的：
>
> 1. **一张图片同时送入 1 个学生 + 3 个教师**。代理模型（1.9B 的学生）前向得到它的 class token 和 patch tokens；三个冻结教师各自独立前向，得到各自维度的 class token 和 patch tokens。
> 2. **Adapter 头做"翻译"**。由于每个教师的输出特征维度都不同（PEcore、PElang、DINOv3 各有各的维度），不能直接比。论文的解法是：为每个教师准备一组**独立的** Adapter 头（一个适配 class token，一个适配 patch tokens，本质上是两层 MLP），把代理模型的输出投影到该教师的特征空间，实现维度对齐。
> 3. **损失分两部分计算**。对齐之后，对每个教师分别算 loss：
>    - **class token 损失**：使用余弦相似度，衡量投影后学生 class token 与该教师 class token 的方向一致性
>    - **patch tokens 损失**：余弦相似度 + Smooth L1 的加权组合（权重 α=0.9、β=0.1），既保证语义方向一致，又约束具体数值接近
> 4. **三个教师的损失直接求和**。PEcore 的 loss + PElang 的 loss + DINOv3 的 loss，不需要加权，因为论文实验发现简单求和效果最好。
> 5. **梯度回传更新代理模型和所有 Adapter**，三个教师全程冻结不动。
>
> **两个关键细节**：
> - 由于各教师原生分辨率不同（PEcore/PElang 是 448，DINOv3 是 256），算 patch 损失前还要对较小的 patch 空间做 **2D 双三次插值**对齐
> - 三个 Adapter **参数独立**且**各自训练**，让代理模型能"同时"对齐到三个不同特征空间
>
> **简言之**：每个教师都有专属的"翻译器"（Adapter），把学生输出翻译成这个教师能理解的语言，再算损失。这种"多 Adapter 独立对齐"设计，避免了强行把三个不同特征空间统一到一个公共空间的难题。

4. **反向传播更新代理模型参数 + 所有 Adapter 头参数**，三个教师全程冻结。

**为什么代理要 1.9B 这么大？** 三个教师特征空间差异大（CLIP 类 vs 自监督类），小模型容量不够"同时吸收"。1.9B 才有足够容量把多种表示统一到同一个空间里。

**训练配置**：
- **图像归一化**：标准 ImageNet 均值/方差对输入图片做归一化
- **特征归一化**：由于三个教师的输出特征尺度各异（有的特征值范围大、有的小），直接对比会导致幅度大的特征主导 loss。论文的做法是：
  1. 正式训练前，用 500 个 mini-batch 的数据过一遍三个教师
  2. 对每个教师的输出，按其特征维度（per-coordinate）分别统计均值和标准差（例如 1536 维特征就得到 1536 个 μ 和 1536 个 σ）
  3. 正式训练时，用这些固定统计量对教师输出做标准化：(x - μ) / σ

  操作位置如下（标准化卡在教师推理之后、算 loss 之前）：

  ```mermaid
  graph LR
    A[输入图片] --> B[教师前向]
    B --> C[原始教师特征]
    C --> D["(x-μ)/σ<br>特征归一化"]
    A --> E[代理模型前向]
    E --> F[原始学生特征]
    F --> G[Adapter 投影]
    D --> H[算 loss]
    G --> H
  ```

  > 注意：标准化**只对教师输出做**，代理模型的输出不标准化，因为 Adapter 头会自己学着去对齐归一化后的教师特征空间。

### 2.2 Stage 2：代理模型 → 高效学生（固定分辨率）

**目标**：从 1.9B 的代理模型蒸馏到 ≤100M 的高效编码器。

**具体做法**：

1. **冻结代理模型**（1.9B），只训练学生模型（86M 的 ViT-B）。
2. **固定 256×256 低分辨率**：大幅降低每步计算成本，能跑 39 万步（390k iterations）长周期。
3. **数据增强**：随机缩放裁剪、水平翻转、色彩抖动、高斯模糊、随机 solarization。
4. **Adapter 头**：在学生输出后接一个 2 层 MLP（Linear → LayerNorm → GELU → Linear，隐藏维度 3072），把学生特征映射到教师特征空间。

**训练配置**：
- batch size：8192
- 学习率：2e-5，余弦调度
- 权重衰减：1e-4
- 总迭代：390k

**为什么要长周期 + 低分辨率？** 单步便宜才能跑更多步，让小模型充分学习代理模型的全部能力。

### 2.3 Stage 3：多分辨率微调

**目标**：让小模型适应下游任务的不同输入分辨率。

**具体做法**：

1. **构造图像金字塔**：三尺度 256、384、512。
2. **独立随机采样**：学生和教师**各自**从金字塔中随机选一个尺度（可以不同！）。
3. **短周期微调**：100k 步，batch 4096，lr 1e-5。
4. **从 Stage 2 checkpoint 初始化**学生模型。

**为什么教师学生可以选不同尺度？** 这是一种"数据增强"——学生见过比教师更细粒度（高分辨率）或更粗粒度（低分辨率）的输入，学会在不同粒度下与代理对齐。

**为什么用短周期？** Stage 3 一次迭代耗时是 Stage 2 的 2 倍（要处理三个尺度），长周期成本太高。

### 2.4 蒸馏过程详解：蒸馏什么？怎么算损失？

**这是 EUPE 最精巧的部分**。蒸馏的不是分类 logits，而是**中间特征（class token + patch tokens）**。每个教师和学生的输出都包含两类 token：

- **Class token**：全局表示，一个向量
- **Patch tokens**：空间表示，\(N \times d\) 矩阵（\(N\) 个 patch，每个 \(d\) 维）

**单教师蒸馏流程**（适用于所有阶段）：

![](https://raw.githubusercontent.com/Liwx1014/PicBed/main/imagesa774283765a8208bfc531ad8861b943474b55b3a9f7e79299dae63893051ba8e.jpg)
*图：单教师蒸馏流程。雪花=冻结参数，火焰=可训练参数。2D 插值用于学生/教师 patch 空间尺寸不一致时*

具体步骤：

1. **前向计算**：学生 \(S(\cdot;\theta)\) 和教师 \(T_i(\cdot;\phi_i)\) 各自输出 \(y^c, y^p\)。
2. **Adapter 映射**：学生 token 通过 2 层 MLP 适配头 \(H_i^c, H_i^p\) 升维到教师特征维度 → 得到 \(z_{T_i}^c, z_{T_i}^p\)。
3. **2D 插值**：把较小的 patch token 空间上采样到较大一方，确保形状一致。
4. **特征归一化**：教师 token 减均值除标准差（见 2.5 节）。
5. **计算损失**：

**Class token 损失（余弦相似度）**：

\[
L_i^c(z_{T_i}^c, \bar{y}_{T_i}^c) = \mathcal{L}_{\cos}(z_{T_i}^c, \bar{y}_{T_i}^c)
\]

**Patch token 损失（余弦 + Smooth L1 加权）**：

\[
L_i^p(z_{T_i}^p, \bar{y}_{T_i}^p) = \alpha \mathcal{L}_{\cos}(z_{T_i}^p, \bar{y}_{T_i}^p) + \beta \mathcal{L}_{\text{smooth-L1}}(z_{T_i}^p, \bar{y}_{T_i}^p)
\]

其中 \(\alpha=0.9, \beta=0.1\)。

**总损失**（Stage 1 对所有教师求和，Stage 2&3 只有 1 个教师）：

\[
L = \sum_i L_i^c + L_i^p
\]

### 2.5 特征归一化：稳定训练的关键

**问题**：不同教师的 class token 和 patch token 的均值/方差差异巨大（参考 UNIC 论文的发现）。如果不做归一化，单个教师（通常是 class token）会**主导梯度**，导致其他教师贡献被淹没。

**EUPE 的简化做法**（比 RADIOv2.5 的复杂 PHI-S 归一化更简单）：
- 每个教师输出 token：\(\bar{y} = (y - \mu) / \sigma\)
- 统计量在训练前用 500 次迭代预先计算，整个训练过程**固定不变**
- 相比 UNIC 的在线 EMA 方案：节省 GPU 内存，易于多节点扩展

> **小结**：EUPE 蒸馏的不是"最终答案"，而是"中间表示"。通过 Adapter 升维 + 2D 插值对齐 + 特征归一化，把多个异质教师的特征统一蒸馏到代理/学生中。这种"中间特征级蒸馏"比"logit 级蒸馏"保留了更多空间信息，对密集预测任务尤其关键。

### 2.6 三阶段配置总览

| 阶段 | 操作 | 关键参数 |
|------|------|----------|
| **Stage 1** | 3 个基础教师 → 1.9B 代理模型 | 多教师蒸馏，256×256 固定分辨率 |
| **Stage 2** | 代理模型 → 86M 学生 | 固定 256×256 训练 390k 步 |
| **Stage 3** | 多分辨率微调 | 256/384/512 三尺度，100k 步 |

## 三、教师怎么选？这事儿有讲究

**Stage 1 用哪几个教师**直接影响最终能力分布。研究者踩了不少坑：

| 教师组合 | 效果 |
|---------|------|
| PEcore-G + DINOv3-H+ | 图像理解 + 密集预测强，但 VLM（OCR）差 |
| + SigLIP2-G | 反而**严重损害** OCR（两个 CLIP 类模型特征冲突）|
| **+ PElang-G（最终选择）** | OCR 与 VLM 大幅提升，且不影响其他能力 |

最终敲定的"铁三角"：

- **PEcore-G**（1.9B）：CLIP 风格，图像理解 + VLM 主力
- **PElang-G**（1.7B）：语言增强版，OCR 任务的关键
- **DINOv3-H+**（840M）：自监督专家，密集预测 / 分割 / 匹配

注意那个反直觉的发现：**别同时塞两个 CLIP 风格模型**（如 PEcore + SigLIP2），它们会"打架"。

## 四、效果有多强？数据说话

### 4.1 EUPE-ViT-B vs. 同尺寸各方模型

在 11 个基准测试上，**EUPE-ViT-B（86M）几乎全面领跑**：

| 任务域 | 指标 | EUPE-ViT-B | 最佳同尺寸 | 表现 |
|--------|------|-----------|-----------|------|
| 图像理解 | IN1k-ZS | **79.7** | SigLIP2-B 78.2 | **超越所有专家** |
| 图像理解 | IN1k-KNN | **84.1** | SigLIP2-B 83.2 | **超越所有专家** |
| 密集预测 | ADE20k（mIoU） | **52.4** | DINOv3-B 51.8 | **超越密集预测专家** |
| 密集预测 | SPair（PCK） | 51.3 | DINOv3-B 51.3 | **追平** |
| VLM | TextVQA | 50.4 | SigLIP2-B 51.6 | 略低 1.2（可接受）|
| VLM | RealworldQA | **55.5** | RADIOv2.5-B 54.3 | **超越所有** |
| VLM | POPE | **85.9** | PEcore-B 85.8 | **超越所有** |
| VLM | GQA | **67.3** | DINOv3-B 65.9 | **超越所有** |

**一句话总结**：用一个 86M 的小模型，在三个不同任务域上**全都达到了 SOTA 水平**。

### 4.2 小尺寸更香

EUPE 家族覆盖 **ViT-T (6M) → ViT-S (21M) → ViT-B (86M)** 和 **ConvNeXt-T/S/B**：

- **EUPE-ViT-T (6M)**：比同尺寸 PEcore-T 在密集预测上提升 **15+ 个点**
- **EUPE-ViT-S (21M)**：逼近 DINOv3-ViT-S 的密集预测水平，同时**还支持 VLM**
- **EUPE-ConvNeXt-T/S/B**：在 VLM OCR 和密集预测上**全面超越 DINOv3-ConvNeXt**

### 4.3 端侧延迟实测

| 模型 | 参数量 | 256×256 延迟 | 512×512 延迟 |
|------|--------|-------------|-------------|
| ViT-T | 6M | **6.8ms** | 38.3ms |
| ViT-S | 21M | 17.1ms | 97.9ms |
| ViT-B | 86M | 55.2ms | 305.2ms |
| ConvNeXt-B | 89M | 59.3ms | 222.7ms |

延迟均在 iPhone 15 Pro CPU 上测得，**完全可落地**。论文还特别提到一个细节：**ConvNeXt 的 FLOPs 虽低，但 CPU 端延迟不一定低**，因为 conv 操作的优化不如 GEMM（ViT 用到的矩阵乘）。

## 五、消融实验：为什么代理模型策略有效？

### 5.1 三阶段缺一不可

| 配置 | IN1k-ZS | TextVQA | ADE20k |
|------|---------|---------|--------|
| Stage 2 only（直接多教师 → 小模型） | 79.6 | 46.8 | 41.9 |
| Stage 1&2（加代理） | 79.5 | 48.3 | 43.3 |
| Stage 1&3（多分辨率） | 80.0 | 49.5 | 52.0 |
| **Stage 1&2&3（完整）** | **79.7** | **50.4** | **52.4** |

- 不加 Stage 1（代理模型）→ VLM 和密集预测都拉胯
- 不加 Stage 2（长训练）→ VLM 质量不够
- 不加 Stage 3（多分辨率）→ 空间细节丢失
- **三阶段缺一不可，才能达到最佳均衡**

### 5.2 越多教师越好？不一定

将代理模型从 1.9B 扩到 7B + DINOv3 从 H+ 扩到 7B：

| 配置 | IN1k-ZS | TextVQA | SPair |
|------|---------|---------|-------|
| 1.9B 代理 | 79.7 | **50.4** | 51.3 |
| 7B 代理 | 80.2 | **48.5** ↓ | 52.0 |

虽然代理本身能力提升了，但**蒸馏到 86M 学生时 VLM 出现明显退化**。原因：教师（7B）与学生（86M）容量差距太大，蒸馏效率反而下降。

未来工作可能需要 **Teaching Assistant 渐进蒸馏**（即在 7B → 86M 中间加一个 500M 级别的"助教"）。

### 5.3 三阶段共用同一套数据配置

论文的三个阶段（Stage 1 多教师蒸馏、Stage 2 固定分辨率蒸馏、Stage 3 多分辨率微调）使用**完全相同的训练数据**：

- **LVD-1689M**：DINOv3 论文构建的大规模预训练数据集，包含约 16.9 亿张图片，对互联网上的各类视觉概念进行了均衡覆盖
- **ImageNet1k**（补充）：128 万张标注图片

**采样策略**很巧妙 —— 每步迭代的 batch 分为两类：
1. **同质 batch**（homogeneous）：全部从 ImageNet1k 采，确保有标注的高质量图片被持续混入
2. **异质 batch**（heterogeneous）：从 LVD-1689M 中随机采，保证视觉多样性

从 ImageNet1k 采样的概率固定为 **10%**，其余 90% 来自 LVD-1689M。

> **为什么不全部用 LVD？** ImageNet1k 虽然量小，但它是人工标注的、类目均衡的基准数据。以 10% 的比例持续掺入训练，相当于给模型"定期回看标准答案"，防止在海量无标注数据中漂偏。

#### 数据质量 vs 数据数量

论文用一个消融实验直接证明了数据质量的重要性：用 **MetaCLIP（25 亿张，多 0.8B）** 替换 LVD-1689M，其余配置完全不变：

| 训练数据 | 规模 | IN1k-ZS | TextVQA | SPair | POPE | Realworld |
|---------|------|---------|---------|-------|------|-----------|
| 90% MetaCLIP + 10% IN1k | 2.5B | 79.3 | 48.5 | 49.0 | 83.9 | 54.2 |
| **90% LVD + 10% IN1k** | **1.69B** | **79.9** | **48.6** | **51.5** | **85.8** | **55.1** |

LVD 虽然少了近 8 亿张图片，但在几乎所有 benchmark 上都更强 —— SPair 提升 2.5、POPE 提升 1.9、Realworld 提升 0.9。这说明 **LVD 的数据质量远高于 MetaCLIP**，也再次印证了"数据质量 > 数据数量"这一屡试不爽的结论。

## 七、我的看法

这篇工作给我几个**关键启发**：

1. **"先聚合再蒸馏" 的方法论很普适** —— 这不仅限于视觉编码器，在 LLM 压缩、多模态模型小型化等场景可能都适用。核心思想是"先用大容量代理模型把多个专家的知识整合起来，再蒸馏给小模型"。

2. **教师组合比单教师质量更重要** —— PEcore + SigLIP2 同时使用反而效果更差，提醒我们"**多教师不一定是 1+1≥2**"，需要考虑特征空间的兼容性。

3. **"小而通用" 的时代来了** —— 在端侧 AI 越来越重要的今天，86M 模型能跑满 11 个 benchmark 而不输专精大模型，是非常务实的工程贡献。

4. **数据质量 > 数据数量** —— 又一次验证。DINOv3 的 LVD-1689M（1.69B）击败 MetaCLIP（2.5B），印证了 Meta 内部对数据质量管控的功力。
